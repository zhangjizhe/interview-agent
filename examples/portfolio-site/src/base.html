Engineering notes

工程手记

从已有项目实践出发，记录我关注的问题与设计取舍。

01　流式消息结束，业务流程就结束了吗？SSE / 状态管理

在 interview-agent 的交互中，消息展示和业务状态分别处理。流式回复结束后，还需要核验服务端状态，再决定用户能否提交下一次回答。把两者直接等同，容易出现界面显示完成、流程却尚未就绪的问题。

请求标识与生命周期清理也很关键：切换会话后，旧请求的增量消息和异常回调不应继续修改当前会话。

02　接入多个 CTI 服务商，适配层解决什么？架构 / 实时通信

服务商的呼叫控制方法和事件模型可能不同。把差异收敛到控制层与适配层，业务组件才不必直接理解每一家服务商的协议细节。

适配接口之外，还要关注长连接状态、本地界面状态和弱网异常之间的一致性。这也是 CTI 平台前端建设中的重要工作。

03　测试关注正常流程，也关注迟到的响应。Vitest / Playwright

对话应用中，一次请求可能超时、取消，也可能在用户切换会话后返回。interview-agent 的测试实践覆盖请求超时和旧响应隔离等场景，并配套浏览器流程测试。

我的关注点是：一次意外响应会不会污染当前会话？一次异常会不会让用户再也无法继续？这些边界值得和正常流程一起验证。
