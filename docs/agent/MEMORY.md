# 记忆与检索

最后更新：2026-08-13

## 当前运行事实

- Redis 提供会话消息、工作状态和摘要状态。
- Mem0 和 Milvus 用于长期记忆。
- 简历被解析并写入按用户隔离的检索上下文。
- Milvus 题库结合 Dense Retrieval、BM25、RRF 和 Rerank。
- Qdrant 提供 Knowledge Base 存储与召回。

工作状态包含 covered skills、score history 等信号，但它不是持久化 Candidate Skill Profile，不得作为用户成长图的事实来源。

## 产品规则

- 简历/JD/知识检索应表现为准备上下文，而不是向用户暴露向量基础设施。
- 记忆和检索不能突破用户资源归属边界。
- 检索到的来源材料应内部可归因，并支持生成评估证据。
- 候选人界面不得在没有明确产品合同的前提下泄露隐藏上下文、原始检索内容或私人记忆。

## P0 数据要求

必须分离目前混在运行时状态中的三类信息：

1. 候选人提供的证据：简历、JD、回答、保存的知识。
2. 评估证据：回答如何支持或未满足技能期待。
3. Agent 上下文：用于生成下一次回复的短期记忆/检索。

只有前两类属于长期的技能/准备度模型。
