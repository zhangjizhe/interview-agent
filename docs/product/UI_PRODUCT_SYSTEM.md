# Product UI System

最后更新：2026-08-20

## Principle

UI 是产品合同的一部分。每个页面必须服务一个明确用户任务、真实数据状态和可验证操作，不能用静态成功状态、内部 Agent 信息或营销式排版掩盖流程缺口。

## Interview

用户：候选人。

首要问题：我离目标岗位还有多远，下一步应该做什么。

信息架构：

```text
首页
训练
面试记录
能力
岗位与资料
设置
```

视觉和交互：

- 左侧或紧凑顶部导航；移动端优先首页、训练、面试记录。
- 首页以当前岗位、证据置信度、能力缺口和唯一下一步为中心。
- 面试房间保持沉浸，题目、进度、回答和恢复操作优先；不显示模型、Prompt、Token、工具或检索细节。
- 报告、技能、训练必须有真实 API 数据；无证据时展示下一步，不显示伪造评分。

## Agent Lab

用户：管理员、Agent 工程维护者。

首要问题：系统现在是否受控、可用、可评估、可发布。

信息架构：

```text
控制中心
运行
MCP 与工具
Trace
评测
实验
发布
设置
```

视觉和交互：

- 独立高密度控制台，固定侧栏、顶部运行状态与主工作区。
- 控制操作有明确的空闲、加载、成功、失败和权限状态。
- 运行编排只展示阶段、状态、版本、延迟、成本与受控工具结果摘要；不展示思维链、原始 Prompt 或未脱敏候选人数据。
- 尚未接入的区域只展示“未配置”状态，不构造虚假 Trace、实验或发布结果。

## Shared Requirements

- 默认使用真实后端合同，所有加载、空、失败和权限状态都有设计。
- 工具操作使用图标或图标加文字，重要命令具有可理解的名称与禁用状态。
- 所有宽度支持桌面、平板、移动，避免横向溢出。
- 颜色表达状态，不单独承载信息；错误不泄露内部服务详情。
- 每次 UI 改造均需通过类型检查、组件测试、浏览器主路径和移动端检查。
