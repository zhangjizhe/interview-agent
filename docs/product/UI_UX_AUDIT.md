# UI/UX 审计

最后更新：2026-08-13
方法：对当前 React 路由及其 API 合同进行源码审计，不代表已完成线上可用性测试。

| 页面/能力 | 用户目标 | 当前状态与摩擦 | 建议改动 |
| --- | --- | --- | --- |
| Landing | 注册前理解产品价值 | 没有 Landing 路由，未登录用户直接看到登录卡片。 | 获客阶段再补产品化入口；不应阻塞 TASK-002。 |
| 登录/注册 | 保护个人训练数据 | 密码流程可用，但没有解释训练闭环或登录后的下一步。 | 说明简历/隐私用途，新用户首次登录后进入岗位设置。 |
| Onboarding | 快速建立目标上下文 | 缺失；当前“新面试”弹窗混合岗位选择和简历上传。 | 改为三步：目标岗位、简历、可选 JD。 |
| 首页/仪表盘 | 决定下一步做什么 | 展示 Token/成本、工具状态、用户 ID、空房间清理和面试列表，无法回答准备度、缺口或下一步。 | 训练状态为主，开发/运维信号移至设置或管理员区域。 |
| 简历 | 提供个人证据 | 上传嵌在弹窗中，房间内有替换入口，解析结果需独立确认。 | 建立可复用简历摘要，展示解析状态、修正、时效和与目标岗位的关系。 |
| 岗位/JD | 让训练对齐目标岗位 | 岗位和职级只在创建面试时出现；没有 JD。 | 在岗位技能分析前引入当前目标岗位和可选 JD。 |
| 面试房间 | 体验专业面试 | 现有全屏聊天耦合简历抽屉、内部 Agent 事件、工具控制、Token 计数与报告。 | 拆分面试、评价、复盘模式；只展示进度、技能、难度、问题、回答和计时。 |
| 评价 | 理解分数原因 | 现有报告只有总分、四个宽泛维度和自由文本优缺点建议，没有回答级证据、技能分数或对比。 | 围绕证据、技能拆解、面试官期待、改进行动和置信度重建报告。 |
| 技能 | 查看长期成长 | 缺失；`coveredSkills` 和 score history 是临时 working state，不是用户档案。 | 必须先持久化技能评估，再绘制趋势。 |
| 训练 | 知道下一步练什么 | 缺失。 | 仅从已记录的能力缺口生成；P0 先做单技能训练，再做完整周计划。 |
| 知识库 | 加入能改善训练的资料 | 现有知识与题库能力偏管理端且暴露检索概念。 | 面向候选人按岗位/技能组织知识集合，管理员治理独立保留。 |
| 题库 | 治理题目质量和覆盖 | 现有页面提供管理、搜索、导入，主要服务管理员。 | 保持管理工具定位；后续向候选人展示推荐原因，而非原始语料管理。 |
| 设置/使用量 | 管理账号与额度 | 已有工具偏好；顶部展示 Token，但没有额度合同。 | 集中账号/工具偏好；只有具备服务端强制能力后再展示真实使用量。 |

## 系统性结论

1. 全局导航将产品描述为“AI 面试官”，并将 MCP/工具/Token 机制置于用户结果之前。
2. 当前首页支持运营一场面试，却不支持决定训练行动。
3. 当前 Report 与 AnswerHistory 缺少统一技能标签、证据锚点、置信度和参考期待，无法证明技能分数。
4. 当前 Interview 组件耦合聊天、内部状态、简历管理、HITL 和评价，体验更接近 Agent 控制台。
5. 已有鉴权、资源归属、简历解析、出题、SSE、报告、成本追踪和浏览器验收资产应复用，不应推倒重来。
