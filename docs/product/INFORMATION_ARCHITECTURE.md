# 信息架构

最后更新：2026-08-13

## 导航模型

导航应围绕训练闭环，而非普通 SaaS 分类。

| 区域 | 用户为什么需要 | P0 状态 |
| --- | --- | --- |
| 首页 | 看到当前准备度与唯一最优下一步。 | 新增，替代当前首页重心。 |
| 练习 | 开始完整模拟或单技能练习。 | P0。 |
| 面试记录 | 继续、复盘或比较面试尝试。 | 由现有列表演进。 |
| 技能 | 查看长期技能证据、趋势与置信度。 | 数据合同完成后进入 P0。 |
| 知识库 | 添加能提升训练质量的岗位相关材料。 | P1 面向候选人的能力；保留现有管理能力。 |
| 题库 | 治理题目覆盖度与质量。 | 管理员导向，保留现有路由。 |
| 报告 | 查看已完成的评价与面试回放。 | P0，独立于面试房间。 |
| 使用量 | 了解模型额度与估算成本。 | P0 设计，后端前置条件属于 P1。 |
| 设置 | 管理账号、目标岗位、隐私和工具偏好。 | P1，现有工具设置迁入此处。 |

移动端优先展示首页、练习、技能和报告。管理员知识库与题库管理不应进入候选人的主导航。

## 核心实体与状态

```text
用户
  -> 当前目标岗位
     -> 简历版本 + 可选职位描述 + 岗位技能图谱
     -> 面试会话（完整模拟 | 技能练习）
        -> 评估证据
        -> 面试评价
     -> 候选人技能档案
     -> 训练计划 / 训练项
     -> 复面比较
```

当前仅存在 `User`、简历检索上下文、`Interview`、消息、答题历史和报告。其余实体是 P0 合同工作，不是现有产品数据。

## 路由方向

```text
/                         首页
/practice                 模式选择与技能练习
/interviews               面试尝试与进行中的会话
/interview/:id            仅面试房间
/reports/:interviewId     评价与回放
/skills                   技能档案与趋势
/knowledge                候选人知识集合（未来）
/question-bank            管理员题库治理
/usage                    额度与成本摘要
/settings                 账号、目标岗位与偏好
```

当前真实存在的路由为 `/`、`/interview/:id`、`/question-bank`、`/tools` 和 `/admin/mcp`。新增路由必须逐步引入，并有鉴权与浏览器验收覆盖。

## P0 信息规则

- 当前目标岗位必须成为一等上下文对象，而不是散落在 UI 查询参数中的字段。
- 报告属于已完成面试，必须在面试房间外打开。
- 技能详情必须展示分数、置信度、趋势、证据数量和最近评估时间。
- 每项训练推荐必须说明触发它的证据与能力缺口。
- Agent、RAG、MCP 和模型内部实现不进入候选人界面。
