# 双端 UI 适配规格

最后更新：2026-09-02

## 目标

在不改变现有领域合同的前提下，让两个应用各自服务于明确的问题：

- **Interview**：候选人离目标岗位还有多远，下一步该做什么。
- **Agent Lab**：管理员能否快速判断系统是否受控、可评估、可发布。

两端共享可访问性、状态和尺寸原则，但不共享信息架构或内容边界。

## Interview

### 信息层级

1. 当前目标岗位与准备度证据状态。
2. 唯一下一步行动。
3. 最近面试与训练建议。
4. 证据不足、错误和额度状态。

### 导航

- 桌面：固定左侧工作台导航。
- 移动：底部四项导航，覆盖首页、面试记录、训练和岗位设置。
- 面试房间保持沉浸，不放入候选人工作台 Shell。

### 页面

- 首页：岗位上下文、准备度、训练路径、最近面试和下一步。
- 训练：一张定向训练卡只说明技能、目标、提示、期望证据和复测行动。
- 岗位设置：表单优先，已保存岗位作为紧凑列表。
- 面试：题目、进度、回答和恢复操作优先；不显示 Agent 内部信息。

## Agent Lab

### 信息层级

1. 控制平面健康、待处理操作和最新发布决定。
2. 当前视图的列表、筛选或命令。
3. 版本、数据集、成本、延迟、失败分类和受控操作结果。

### 导航

- 固定深色侧栏，按控制中心、运行、MCP、Trace、评测、实验、发布和审计组织。
- 操作日志独立于领域审计，但与其使用一致的筛选与分页交互。
- 小屏保留紧凑顶部导航和单列筛选，禁止横向溢出。

### 页面

- 控制中心：受控摘要，不使用营销式数据卡堆叠。
- MCP：每项操作独立 loading/success/error。
- 评测、实验、发布、审计和操作日志：紧凑可扫描列表，优先版本、状态和时间。

## 共享基础

| 类别 | 规则 |
| --- | --- |
| 字体 | 系统无衬线；分数、时长、版本和用量使用稳定的等宽数字。 |
| 间距 | 4px 基础刻度；区块 16/24px；点击目标至少 36px。 |
| 圆角 | 面板和控件 4-8px；不使用装饰性大圆角。 |
| 状态 | 蓝色主操作，绿色已完成，黄色需注意，红色错误；颜色必须配合文字。 |
| 响应式 | 不用视口缩放字体；导航、筛选与长文本均可换行且不挤压操作。 |
| 空态 | 明确说明当前缺少的真实数据和下一步，不制造示例成功数据。 |

## 首轮实施

1. Interview Shell 增加完整移动导航、统一页面画布和状态样式。
2. 调整候选人首页/训练页的页面头、区块层级和行动优先级。
3. 调整 Agent Lab 的导航分组、顶栏、操作反馈、筛选布局和移动断点。
4. 以现有 Docker 浏览器验收补充桌面/移动截图，检查不重叠、无内部信息泄露和真实空态。

## 设计审查结论

- Interview 仍保留少量技术管理路由作为兼容入口，但候选人主导航与移动导航只呈现首页、面试记录、训练和岗位设置。
- 训练建议不再在页面读取时隐式触发写请求，用户通过明确的“更新建议”操作刷新真实证据。
- Agent Lab 的运行拓扑是架构示意而非实时状态。无真实数据的控制能力必须显示未配置，不能以动画或静态颜色伪造活动运行。
- Agent Lab 的系统级重新加载需要明确说明作用范围；本轮使用浏览器确认，后续可在操作日志和不可逆操作扩展中统一为 Dialog。
