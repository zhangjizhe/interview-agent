# Agent Lab UI Operating System

最后更新：2026-08-19

## 定位

Agent Lab 是管理员使用的 Agent 控制平面，不是 Interview 候选人页面的技术抽屉。界面围绕治理、
可观测性、评测和发布决策组织，不能展示未脱敏候选人原始对话、简历、Prompt 或思维链。

## 信息架构

```text
概览
运行
MCP 与工具
Trace
评测
实验
发布
设置
```

当前 V0.1 仅启用：

- 概览：控制面服务摘要和待处理状态。
- MCP 与工具：系统级服务状态、启停、健康检查和配置重载。

其余项目必须显示为未配置状态，不能用虚构数据或静态成功状态代替真实合同。

## 操作规则

- 系统级操作只允许 `ADMIN`，并经现有 NestJS RBAC API 执行。
- 每次操作必须有空闲、进行中、成功和失败状态；错误来自 API 的安全业务消息。
- 服务健康检查是单服务操作，必须独立请求和独立反馈，不能让一个服务的等待状态阻塞其他操作。
- 配置重载不会自动表示持久化成功或发布完成；未来发布操作需要审批、审计和回滚记录。
- Agent Lab 不保存管理员令牌，不在构建期注入密钥；仅使用已有浏览器会话对同源 API 的授权请求。

## 视觉规则

- 控制台优先信息密度、稳定布局和扫描效率，不使用候选人训练页的鼓励性文案或聊天式布局。
- 操作使用熟悉的图标、明确的命令按钮与状态徽标；不可逆或影响所有用户的操作需在后续版本加入确认与审计。
- 页面区块不是漂浮卡片堆叠。列表项、面板和对话框才使用明确边框。
