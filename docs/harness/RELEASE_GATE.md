# 发布门

最后更新：2026-10-07

## 发布条件

Agent/评估器/运行时变更只有在满足以下条件时才能发布：

1. 相关单测、集成测试、typecheck 和浏览器测试通过；
2. 相关数据集有效，且已记录对比结果；
3. 质量和安全指标满足阈值，或有明确人工批准；
4. 延迟与估算成本变化对目标流量可接受；
5. 新失败已完成分类，且没有未解决的严重回归；
6. 已记录 Trace、Prompt/Agent、数据集和评估器版本。

## 决策结果

| 结果 | 条件 |
| --- | --- |
| `APPROVE` | 质量/安全通过，且成本/延迟在允许范围内。 |
| `NEEDS_REVIEW` | 质量提升但成本/延迟显著增加，或证据不足。 |
| `REJECT` | 质量/安全退化、输出无效或存在未解决严重失败。 |

真实 Provider 验证受成本和凭据限制，应保持有界。它补充确定性测试，不能替代确定性测试。

## 成本证据合同

- 每次模型调用必须记录实际 Provider、Model、输入 Token、输出 Token 和可用的缓存输入 Token。
- 成本只能使用带版本号、币种、生效时间、官方来源和计价口径的费率目录计算；环境覆盖必须通过完整合同校验。
- 同一批证据中任一有计费 Token 的调用无法匹配费率时，成本状态为 `unavailable`，发布门不得把零值当作已核验成本。
- Provider 账单抽样对账默认容差为 5%；超出容差标记 `mismatch` 并进入人工复核。没有账单样本时只声明工程估算，不声明财务对账通过。

## `release-gate/v3` 质量证据

- 发布 Dataset 必须冻结、带内容指纹，并满足 `DATASET.md` 的最小样本量和业务切片合同。
- 候选与当前版本基线必须使用同一 Dataset、Evaluator、内容指纹和重复次数。
- 候选与基线按 Case key 成对比较；配对缺失、样本少于 10 或切片证据不可用时拒绝发布。
- 成对分差的双侧 95% 区间下界必须不低于 `-2` 分；任一岗位族、技能或难度切片平均回归不得超过 5 分。
- 原有全部 Case 通过、最低 90 分、P95 延迟/Token/成本回归不超过 20% 的门禁继续生效。
