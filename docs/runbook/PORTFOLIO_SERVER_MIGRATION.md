## 迁移前必须补齐

- 在目标机“关于本机”或当前系统信息中核实型号、CPU、内存、系统类型和完整版本；确认是否通过非官方补丁安装。
- 核对可用磁盘、磁盘健康、持续供电、有线/稳定网络和休眠策略。不要先抹盘、重装或删除旧机器内容。
- 根据上述实际系统核对官方 Docker 支持条件，再决定继续当前系统或采用其他已授权方案；本稿不指定未经核实的系统版本。
- 确认固定域名/受管理隧道的账号与访问条件。临时 Quick Tunnel 仅用于试接，不能作为长期交付通过条件。

## 可执行的迁移顺序

1. **冻结交付版本**：保存当前已验收提交、已发布 Agent 版本、Site版本与环境修订号。保持旧机服务可恢复；不将本地未验收改动混入新镜像。
2. **盘点并备份**：在受控切换窗口备份 PostgreSQL、Redis 持久化状态以及实际使用的向量/文件数据。Redis 的请求幂等与 active 状态不能当普通缓存清空。先核实向量服务状态和存储归属；不能把未运行、未检查的数据写成已备份。
3. **单独迁移秘密**：用目标系统的安全凭据存储配置模型、邮件、网关及票据凭据。不要把 `.env`、Keychain 导出、数据库备份或运行记录上传 GitHub/聊天/公开站点；保持原账户与授权，不直接改数据库发布 Agent。
4. **本机恢复验证**：目标机端口先只绑定回环，恢复数据后核对登录/RBAC、工作区归属、正常发布版本、历史报告、Run/Trace、Redis幂等与实际用量。重新启动必须验证手动密钥注入后才就绪；未经授权不安装后台 Keychain 读取器。
5. **配置稳定公网入口**：只转发受限公开网关，管理/登录/数据库不开放。验证管理路由404、缺密钥401、来源检查以及请求/响应边界。
6. **单点切换 Sites**：只修改服务端地址 Secret，保留其他凭据和公共访问范围，重新部署已保存的对应版本。切换后先检查无模型的连通性与围栏，再按持久账本预留最多0.03CNY进行一次真实问答。
7. **最终验收**：真实浏览器的回答与引用、无关问题拒答、同请求不重复收费、报告和 Run/Trace 可追踪；目标机重启后的人工恢复、备份还原和持续运行条件均需要实际证据。合成检查不得替代真实 Provider 与部署验证。

## 回滚与失败处理

保留旧机及原始数据卷、版本和私有配置。目标机检查失败时停止切换，先确认在途请求与费用；不要以新 UUID、删 Redis 或提高额度掩盖未知结果。已经切换后出现问题，只在确认旧入口健康且数据写入归属后恢复原 Sites 地址；禁止双机同时作为可写主库。未完成数据同步时不能直接切回旧库。

本准备稿不包含目标机连接凭据，也未执行目标机安装、数据导入、域名配置或切换。下一步输入：目标系统类型/完整版本、内存、可用磁盘与可访问方式。
