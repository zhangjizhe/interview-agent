# Lab 自定义 Agent 与编排产品合同

更新：2026-10-08；属于 PRODUCT-REACCEPTANCE-1。用户已要求新增并整体完善；本合同不能代表功能已交付。

## 用户闭环

管理员在自己的 workspace 创建 Agent，配置名字、唯一 key、用途、系统提示、已支持的模型、输入输出合同与工具绑定；保存为不可变版本草稿。草稿可在受控测试入口执行和查看 Trace，经过数据集/评测/发布门才成为正式版本。刷新可读回，失败不会显示成功；创建失败不得留下伪版本，重复点击不得重复创建。使用现有 Registry、Run、Trace、发布门、Tenant Context 与 Gateway，不建立绕过权限或计量的新入口。

工作流必须是真实执行定义：节点引用明确的 Agent 版本，边定义输入输出映射、顺序、条件与失败处理；保存和校验同样版本化。首版限制无环图、最多十个节点、单轮串行，不提供任意代码/URL/命令执行。节点必须属于当前 workspace；发布后引用冻结，不随其他 Agent 升级漂移。编辑器显示配置与校验结果，运行视图显示本次节点状态与时间，静态架构图不能替代编辑器或运行证据。

## 安全、费用与失败合同

- 管理接口要求 ADMIN；跨组织或 workspace 引用统一拒绝，不通过用户传入组织 ID 改归属。权限变更仍由部署所有者控制。
- 模型只能选网关已注册 provider，调用前有 quota reservation、输入/输出 Token 和节点/总调用限额；费用未知显示未知，不记为零。工具复用 ToolRunner 的白名单、审批、Trace 与 RunBudget；不能直接执行 Registry.execute 绕过这些边界。
- 保存配置不触发模型。非付费验收使用禁止外网的隔离服务和明确的 fixture；真实模型质量测试仍需核对历史未知账单/额度并确认新有界预算。
- Run 和节点执行状态持久化；刷新不重复执行。取消阻止后续节点，在途调用单独结算。失败停在准确节点，默认不隐式重试产生新费用；显式新运行与原运行关联。
- 首版不承诺持久化断点自动恢复、任意循环、并发、任意插件安装或凭据编辑。相关能力须另外规划，界面不得提供可用承诺。

## 分阶段退出门

用户仓库要求每 Phase 完成后等待继续。将新增范围拆为可核验阶段，整体一直保持 NOT_ACCEPTED：

1. 基础阻断阶段：修复题库读取和 MCP 重载/错误展示；实际镜像 HTTP、向量列表与浏览器双证据。仅证明这些修复。
2. Agent 阶段：Registry 创建/配置 UI、通用运行适配、受控草稿运行和费用/工具边界；隔离真实 API 与浏览器闭环通过。
3. 编排阶段：采用 ADR 确定版本存储与执行状态；可编辑定义、实际执行、节点 Trace、预算/取消；隔离完整链路通过。
4. 全产品阶段：合并原全产品验收计划，逐项展开全部交互/展示，真实模型质量与费用在明确预算内验收，固定 SHA/镜像与远端 CI 后才能交付。

当前只有第一阶段正在测试；自定义 Agent 入口、通用执行器和真实工作流编辑执行尚未完成。MCP TCP/绑定检查不等于真实 MCP initialize/listTools/callTool，题库新增/语义搜索也尚未完成统一计量验收。
